# Безопасность и политика scope

## Принцип авторизации (fail-closed)

Hacking-Aziral запускает разведку **только в пределах авторизованного scope**.

- Каждый скан обязан ссылаться на `Target` с заданным scope.
- Пустой scope = **ничего не разрешено** (fail-closed) — см. `app/scope/gate.py`.
- В режиме `SCOPE_MODE=enforce` запуск вне scope → HTTP 403 + запись `audit_log`.
- В режиме `SCOPE_MODE=warn` запуск разрешён, но помечается WARN и логируется.

## Что входит в scope

| Поле | Что разрешает | Правило совпадения |
|---|---|---|
| `domains` | домен и его поддомены | `acme.com` → `acme.com`, `api.acme.com` |
| `emails` | конкретные email + email по домену из `domains` | точное или домен в scope |
| `usernames` | конкретные username | точное совпадение |
| `hosts` | конкретные хосты | точное + поддомен по `domains` |
| `ip_ranges` | IP в CIDR | `10.0.0.0/24` |

## Управление секретами

- Все секреты — только в `.env` (в `.gitignore`), генерируются `scripts/gen-secrets.sh`.
- Никаких ключей в коде или образах. AI-ключи проходят через `sub2api`.
- На проде: `ACME_CA=production`, сильные пароли, ограниченный доступ к Authentik.

## Сетевой контур

- Внешний доступ — только через Traefik (TLS) + Authentik forward-auth (SSO на всё).
- БД/Redis/воркеры — во внутренней сети `aziral_internal`, без публикации портов.
- Security-заголовки (HSTS, nosniff, frame-deny) применяются глобально на websecure.
- Rate-limit на запуск сканов (`/api/scans`).

## Аудит

`audit_log` фиксирует: actor (из SSO), action, target, detail, allowed, время.
Записывается при создании цели, запуске и блокировке скана.

## Назначение

Платформа предназначена для **авторизованного** тестирования собственной/разрешённой
инфраструктуры, обучения и CTF. Ответственность за легальность использования — на операторе.
